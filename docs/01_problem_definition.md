# 1. 문제 정의서

> 이 PoC의 대상은 **출시를 준비 중인 개인 게임**이라, 게임 제목·기획 내용·생성 프롬프트·원본 그림은 공개하지 않는다.
> 그림은 작게 줄인 미리보기만 싣고, 그림 이름은 `boss_01`, `weapon_07`처럼 바꿔 적는다.

## 도메인

혼자 만들고 있는 **모바일 다크 판타지 주사위 로그라이트**(제목 비공개)의 그림 리소스 제작.

- 그림은 "거친 유화풍의 어두운 판타지" 화풍 하나로 맞춘다. 화풍 기준 그림이 한 장 있다.
- 지금까지 캐릭터, 적, 보스, 무기, 마을, 던전 방, 타격 효과, 화면 틀 등 **약 80장**을 만들었다.
- 캐릭터·적·무기 그림은 배경을 지운 투명 그림으로 게임에 들어간다 (31장).

## 현재의 문제

### 지금 방식

```
ChatGPT 새 대화 → 기준 그림 첨부 → 프롬프트 붙여넣기 → 생성 → 마음에 안 들면 프롬프트 고쳐 다시 생성
 → 내려받기 → 이름 바꿔 저장 → 배경 제거 (색 기준으로 지우는 별도 작업) → 잘라서 저장 → 게임에 연결
```

### 번거롭거나 비효율적인 점

| 문제 | 내용 |
|---|---|
| **사람이 장마다 붙어 있어야 한다** | 대화 열기, 첨부, 붙여넣기, 내려받기, 이름 바꾸기를 장마다 반복한다. 한 번에 나오면 1분 이내지만, 실패하면 프롬프트를 고치느라 **5분** 정도 걸린다 (개발자 작업 기록) |
| **다시 만들 수 없다** | ChatGPT 이미지는 시드를 고정할 수 없고 네거티브 프롬프트도 없다. 같은 그림을 다시 얻을 방법이 없다 |
| **화풍이 흔들린다** | 매번 기준 그림을 첨부해야 하고, 한 대화에서 여러 번 고치면 화질과 색이 점점 탁해진다 |
| **배경 제거 품질을 아무도 검사하지 않는다** | 배경 제거 결과를 눈으로 대충 보고 넘겼다. 이 PoC에서 확인해 보니 **31장 중 10장에 결함**이 있었다 (`03_evaluation.md`). 배경 제거 그림은 게임 화면뿐 아니라 **스토어 표지 같은 홍보물에도 다시 쓰이므로**, 결함이 게임 밖으로도 퍼진다 |
| **상업 이용 조건이 정리되지 않았다** | 출시 전에 이미지 도구의 상업 이용 조건을 확인해야 한다 |

### 지금 막혀 있는 일

게임 안의 **아이콘 10개**가 아직 그림 없이 글자로만 표시된다.

| 묶음 | 아이콘 |
|---|---|
| 주사위 특수 면 4 | 해골, 불꽃, 방패, 회복 |
| 기술 칸 6 | 내려치기, 화염구, 급소, 도발, 축복, 조준 사격 |

출시 범위를 채우려면 이런 아이콘이 수십 개 더 필요하다. 장마다 사람 손이 드는 지금 방식이 병목이 된다.

## 업무 유형 (레슨의 네 유형으로 나누기)

이 PoC는 두 일을 다룬다.

| 일 | 유형 | 병목 | 판정 기록 |
|---|---|---|---|
| **A. 배경 제거와 품질 검사** | **검사·판독** — 그림의 각 점이 대상인지 배경인지, 결과가 게임에 쓸 만한지 판정 | 판정의 일관성. 사람이 대충 보고 넘겨서 결함이 그대로 게임에 들어갔다 | 게임에 쓰고 있는 배경 제거본 31장 |
| **B. 아이콘 생성** | 네 유형 밖의 **생성**. 정답이 하나로 정해지지 않는다 | 장마다 드는 사람 손, 재현 불가 | 없음 → 생성 전에 기준을 정하고 그 기준으로 채점 |

### 적용하지 않을 조건 점검 (레슨 2장)

| 조건 | A. 배경 제거·검사 | B. 아이콘 생성 |
|---|---|---|
| 판정 기준이 사람마다 다른가 | 아니오. "배경 조각이 남았는가, 대상이 지워졌는가"로 정할 수 있다 | 일부 그렇다. "게임에 쓸 만한가"는 주관이 섞인다 → 체크리스트와 자동 지표를 함께 쓴다 |
| 틀렸을 때 되돌릴 수 없는가 | 되돌릴 수 있다. 그림 파일을 바꾸면 된다 | 되돌릴 수 있다 |
| 판정 기록이 있는가 | 있다 (31장) | 없다 → 기준을 먼저 적는다 |

## 개선 가설

> 배경 제거와 생성을 **내 PC에서 도는 오픈 모델**로 바꾸고 한 번에 이어 붙이면, 아이콘을 **사람이 붙어 있지 않아도** 만들 수 있고 **같은 그림을 다시 만들 수 있다.**
> 같은 배경 제거 모델로 **이미 게임에 들어간 그림의 결함도 자동으로 골라낼 수 있다.**

```
A. 품질 검사:  원본 그림 → BiRefNet 배경 제거 → 게임 배경 제거본과 비교(IoU) → 임계값 아래면 "검토 필요" → 사람이 확인 → AI 결과로 교체

B. 아이콘:     아이콘 목록 → SDXL (시드 4개) → SigLIP 2로 "무엇으로 보이는가" 채점
              → 확신이 높으면 자동 채택, 낮으면 사람 검토 → BiRefNet 배경 제거 → 256×256 투명 PNG
```

## 대상 사용자

- 1차: 나 (그림까지 혼자 만드는 게임 개발자)
- 2차: 그림 담당이 없는 소규모 게임 팀

## 성공 기준 (실험 전에 고정)

| # | 기준 | 목표 | 근거 |
|---|---|---|---|
| ① | 배경 제거: 게임 배경 제거본과 견준 IoU 평균, AI 없는 색 지우기(기준선)보다 높을 것 | **0.95 이상** | 사람 눈에 경계 차이가 거의 보이지 않는 수준 |
| ② | 알아볼 수 있음: 아이콘 10종 중 시드 4장 중 1장 이상이 SigLIP 2 한국어 10지선다를 맞힘 | **8종 이상** | 레슨 검색 예시와 같은 8할 |
| ③ | 화풍: 최종 아이콘의 화풍 유사도가 기존 ChatGPT 아이템 그림 9장끼리의 최저값 이상 | **10개 모두** | 지금 게임에 들어간 그림만큼은 비슷해야 한다 |
| ④ | 사람 손: 자동 채택한 아이콘은 사람 조작 없이 완성 | **조작 0회** | 지금 방식은 장마다 대화·첨부·저장 |
| ⑤ | 기계 시간: 아이콘 1개(생성 4장 + 채점 + 배경 제거) | **3분 이하** | 사람이 붙어 있지 않아도 되는 시간 |
| ⑥ | 재현성: 같은 설정·시드로 다시 돌리면 같은 그림 | **픽셀 차이 0** (같은 PC) | ChatGPT로는 불가능한 항목 |

> 품질 검사기(A)의 기준은 배경 제거본에 결함이 많다는 사실을 실험 중에 알게 된 뒤 추가했다: **결함을 모두 잡는(재현율 100%) 임계값에서 사람이 볼 그림을 절반 가까이 줄일 것.** 사후에 추가한 기준이라는 점을 밝혀 둔다.

### 성능과 상관없이 먼저 거르는 조건

- **실행 위치**: 출시 전 그림과 프롬프트는 외부로 보내지 않는다 → 로컬 실행 모델만 후보.
- **라이선스**: 게임에 결제·광고가 들어가므로 **상업 이용이 안 되는 모델은 탈락** (`02_model_selection.md`).
